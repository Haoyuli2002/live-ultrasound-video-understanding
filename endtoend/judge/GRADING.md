# StreamReady 流式 QA 评分规范 v1

适用输入为 holdout 的 `all_qa.jsonl`。每题一行，`decisions` 给出按时间排序的标注和预测。评分单位分为题、决策时刻。一次 WAIT 后仍可继续观看；首次 ANSWER 即视为用户收到回复。

## 1. 程序计算触发时机

按 `video_window_s[1]` 排序。在当前数据，每题只有一个 GT ANSWER 时刻。设它为 a，模型首次预测 ANSWER 的时刻为 p。p=a 记 on_time，p<a 记 early，p>a 记 late，始终 WAIT 记 missed。比较同一条已标注决策记录即可，无需浮点容差。当一题既有提前触发又有按时触发记录时，该题记 early。对即时题使用相同规则，通常只有一个决策时刻。若未来出现全程 GT WAIT 的题，单报正确等待或误触发，单列分母。

GT WAIT 时只计算动作是否正确。输出文件里即使保存了强制生成文本，也不将其送入内容 Judge。当前 StreamReady 没有面向用户生成 WAIT 原因。所有 timing 指标的分辨率都是已标注的决策时刻。

## 2. Judge 评估答案内容

对**每一道题的 GT ANSWER 时刻**恰好评一次。取该时刻的 `generated_answer`，包括被 readiness 拦下的强制生成答案。按时触发时它也正是实际回复，因此同一个内容分可用于端到端指标。

输入只给题号、样本 ID、问题、GT 答案、候选答案、提问时间、当前时间，以及从视频起点到当前时间的可播放画面。先列出问题要求回答的最小事实，再核对候选答案。历史题回看指定秒，比较题检查前后两个画面，事件题检查变化前后。需要判读 inset 时放大原始视频中的超声区域。截断视频或限制读取器的可寻址时间；单纯把结束时间写进提示词不足以隔离未来画面。候选打分时隐藏实验名、readiness 分数、是否强制生成、自动匹配结果。

| 分数 | 判据 |
|---|---|
| 3 完整正确 | 所有必答事实均符合可见证据，实质性补充也成立。同义表达、简短回答、未复述 GT 中未被询问的附带描述均可给满分。 |
| 2 基本正确 | 核心结论清楚且符合画面。有轻微不精确、次要遗漏或表述略宽，没有引入会改变理解的事实错误。 |
| 1 部分正确 | 至少一个实质性必答事实正确，但缺少另一项必要信息，或附加的方向、位置、对象等重要断言与画面矛盾。例如比较题只答对当前状态，或形状答对又给出相反朝向。 |
| 0 错误或未作答 | 未给出任何被问到的核心事实，关键对象、事件极性或所问方向答错，或答案为空。仅复述题干且没有完成任务也记 0。事件通知中，简短确认事件已发生本身即可构成完整回答。 |

有多个必答事实时，先区分核心信息和 GT 的附带说明。问“哪个器官”需要可识别的器官名称；问“形状或朝向”需要对应属性；问“比较”需要说明历史与当前两个状态及其关系。彩色标尺、课件配色和外部摄影画面的颜色不能证明原生超声区域有血流信号。候选答案与 GT 用词不同但视频支持时，按语义给分。

若视频文件或关键区间不可用、证据无法判读、问题歧义影响等级，或 GT 与可见画面有实质冲突，输出 `review`、`score=null`、原因和需要复核的时间点。可以判断且候选答案含糊时，应给相应低分。每个已评分结果给出至少一个真实可见的时间和观察；历史比较尽可能分别引用两个时间。记录必须通过同目录下的 `content_grade.schema.json`。此外，导入时校验 ID、时刻与输入相符，且所有 evidence 的秒数落在 [0, current_time_s] 内。

## 3. 汇总与分母

| 指标 | 分子 / 分母 |
|---|---|
| ANSWER 正确触发率 | GT ANSWER 且预测 ANSWER 的时刻 / 全部 GT ANSWER 时刻 |
| WAIT 正确率 | GT WAIT 且预测 WAIT 的时刻 / 全部 GT WAIT 时刻 |
| 按时触发且答对率（主指标） | 首次触发为 on_time 且内容分 ≥2 的题数 / 全部可回答题数 |
| 强制生成答案正确率 | GT ANSWER 时刻内容分 ≥2 的题数 / 全部可回答题数，包括当时预测 WAIT 的题 |
| 完整答案率 | GT ANSWER 时刻内容分为 3 的题数 / 全部可回答题数 |

主要报表固定全量分母。存在待复核内容时，给正确率区间：下界只计已确认的正确项，上界再计入可能改变该指标的待复核项；端到端上界只需加入 on_time 且待复核的题。报告待复核数与已评分覆盖率。当前导出有 464 道可回答题、464 个 GT ANSWER、530 个 GT WAIT；分开报 236 道即时题、228 道延迟题和四种 QA 类型。子组无合适分母时填 N/A。并列报告 0/1/2/3 分布、early/late/missed 题数；题级平均不因某题有多个 WAIT 获得更高权重。

## 4. 校准范围

首轮校准来自 BS64 第 100 步的 20 道 holdout QA，每类 5 道，覆盖 16 个视频。按题型和触发情况挑选，查看了英文 Q/GT/候选答案及原视频关键帧，包括历史帧、事件发生前后的帧。这组例子适合解释边界分，不能估计总体正确率或 Judge 与专家的一致率。跨 checkpoint 比较时固定本规范和 Judge 版本。
